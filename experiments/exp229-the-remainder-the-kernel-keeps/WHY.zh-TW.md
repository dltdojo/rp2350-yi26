# 經過證明的有限體運算，和直接用 Rust 或 C 寫有什麼不同

<!-- SPDX-License-Identifier: Apache-2.0 -->

這份文件用白話說明 exp229 做了什麼，並比較它和直接用 Rust 或 C 寫同樣功能的程式差在哪裡。實驗本身的細節在 [README.md](./README.md)（英文）。

## 1. 這個實驗做了什麼

比特幣的簽章（BIP340 Schnorr）建立在一條橢圓曲線上，而曲線上每一次點的加法、每一次倍乘，拆到最底層都是同一件事：**對質數 p = 2²⁵⁶ − 2³² − 977 取餘數的加、減、乘**。這叫做「有限體運算」。硬體錢包簽一次名，要做上萬次這樣的運算；任何一次算錯，簽章就錯，或者更糟，洩漏私鑰。

exp229 寫了這三個運算，並證明它們對。

| 角色 | 在這個實驗裡是什麼 |
| --- | --- |
| 規則書 | `proof/Field.lean` 裡的 `spec`：加法是 (a + b) mod p，減法是 (a + p − b) mod p，乘法是 (a · b) mod p |
| 程式 | `kernel.bin`，458 條 RISC-V（RV32IM）機器指令，把 256 位元的數字拆成 8 個 32 位元的字來算 |
| 證明一 | 定理 `field`：對**每一組** a、b（只要都小於 p），程式都會停下來，結果和規則書一模一樣，而且剛好執行 331、238 或 1903 條指令 |
| 證明二 | 定理 `field_constant_time`：換成任何別的 a、b，程式走過的每一步——讀哪個位址、寫哪個位址、跳到哪裡——都完全相同 |

### 為什麼「每一步都相同」很重要

這叫做**常數時間**。如果程式遇到某些數字會多繞一圈迴圈、或跳過一段，攻擊者只要量時間或量耗電，就能慢慢推出私鑰。這類攻擊（旁通道攻擊）曾經真的從硬體錢包和智慧卡裡偷出金鑰。

所以這支程式**沒有任何依數字決定的分支**。唯一需要「選擇」的地方——結果超過 p 時要不要減掉 p——用的是遮罩：

```
結果 = y ^ ((x ^ y) & 遮罩)
```

遮罩是全 1 就得到 x，全 0 就得到 y。兩種情況執行的指令完全一樣，只有資料不同。

證明二不是靠人看程式碼保證的，而是用 exp207 寫好、本身已被證明正確的檢查器，把 458 條指令逐條跑過一遍。

## 2. 證明逼出來的三個改變

### 副程式不見了

最初的版本只有 190 條指令：加法迴圈、減法迴圈、選擇迴圈各寫一次，用 `jal`（呼叫）和 `jalr`（返回）重複使用，就像一般程式的函式。

但常數時間檢查器不接受 `jal` 和 `jalr`：它能追蹤直線程式和迴圈，卻追蹤不了「返回位址」這種東西。於是每一段都改成**在用到的地方直接展開**，程式長到 458 條。這是用程式大小換取可以被證明。

### 乘法的外層迴圈攤開成八份

乘法是小學的直式乘法：A 的每一個字乘上整個 B，加到結果的對應位置。結果的位置是 `T + 4(i + j)`，同時跟著兩個計數器走。檢查器只認得「固定位置加上**一個**計數器的倍數」，所以外層的八輪被直接寫成八段，每段只剩一個計數器。

### 第三次「折疊」

256 位元乘 256 位元得到 512 位元。因為 2²⁵⁶ 除以 p 的餘數是 2³² + 977，高半部可以乘上這個數「折」回低半部。通常折兩次就夠，只有在極少數情況下第二次還會進位。

exp228 的 C 程式碼用一個 `if` 處理那個極少數情況，而 20 萬組隨機測試**一次都沒有走到那個分支**。換句話說，那段程式從來沒被測試過。

這裡沒有 `if`：第三次折疊永遠執行，而證明說明了它留下的數一定小於 2²⁵⁶，所以最後只要再判斷一次「要不要減 p」就完成。

## 3. 和直接用 Rust 或 C 寫的差別

### 3.1 保證的東西不同

| | 本實驗 | 一般 Rust / C |
| --- | --- | --- |
| 結果對不對 | 對所有小於 p 的 a、b 都證明了 | 測過的那些對；常見做法是幾萬組隨機加上邊界值 |
| 常數時間 | 對真正執行的機器指令證明了 | 原始碼看起來沒有分支；但編譯器可能把遮罩改回分支，要靠反組譯或工具抽查 |
| 執行幾條指令 | 證明了：331、238、1903，與數字無關 | 要量 |
| 證明的對象 | `kernel.bin` 裡的位元組本身 | 原始碼；編譯器在中間 |

最後一列最關鍵。用 Rust 或 C 寫，就算原始碼被證明了，編譯器仍然可能做出意料之外的事——最佳化器把「無分支的選擇」改寫成分支，是真實發生過的案例。這裡證明的是最後要執行的機器碼，中間沒有編譯器。

### 3.2 還得信任什麼

證明不是萬能的。這個實驗仍然需要信任：

- **Lean 本身**，以及 `lean/Rv32` 裡 RISC-V 指令的模型寫得忠實。為此，同一份 `kernel.bin` 也在 Hazard3 處理器的 RTL（硬體描述）上執行，1143 組輸入的結果、指令數都和模型一致。
- **時間模型**：證明說的是「每一步的位址都相同」。在沒有快取、乘法固定週期的核心上，這就等於時間相同；RTL 上量到的週期數（370、266、1979）對每組輸入都一樣，但週期數本身不在證明範圍內。
- **p 放在對的地方**：定理假設記憶體裡 PRIME 位置存的是 p。映像檔確實放了，差分測試也讀回結果驗證，但沒有定理從位元組裡把它讀出來。

### 3.3 要付出的代價

- **程式變長**：從 190 條變成 458 條，乘法從 1876 條變成 1903 條。
- **寫證明的時間**：`proof/Field.lean` 約兩千五百行，其中程式本身只佔 458 行。好在大部分是可以重複使用的：一個「一輪迴圈」的引理，六種迴圈都用它；`lean/Rv32/Limbs.lean` 裡的進位、借位、乘加引理，之後的橢圓曲線運算也會用到。
- **工具的極限**：用 `decide` 逐條比對 458 條指令的位元組時，Lean 記憶體用盡。解法是把「位元組就是指令」證明成對**任何程式**都成立的一般定理（`toBytes_words`），以後不必再逐條計算。

## 4. 下一步

有限體是地基。往上依序是：模反元素（用費馬小定理，同樣無分支）、曲線上的點加法與倍點、純量乘法，最後是 BIP340 簽章。每一層都會沿用這裡的模式：每個迴圈一個不變量，每段程式一個引理，再組合起來；以及同一個常數時間檢查器。
