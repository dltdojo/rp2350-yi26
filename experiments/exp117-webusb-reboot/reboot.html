  Success here looks exactly like failure. The board resets, so the
  device this page is holding disappears mid-request. Expect an error from the
  transfer itself — that is what a device rebooting on command looks like from
  the host's side. The page listens for the disconnect and reports that as the
  result, because the disconnect is the only part that is unambiguous.
  


  On Linux, run yi26 detach first, as in exp116 — the
  kernel's cdc_acm driver owns the interface and an interface has
  one owner. On Android there is no cdc_acm, so there is nothing
  to move out of the way. That asymmetry is the whole reason this track exists.
