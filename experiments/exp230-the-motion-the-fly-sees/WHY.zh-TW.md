# 經過證明的果蠅，看著經過證明的生命

<!-- SPDX-License-Identifier: Apache-2.0 -->

這份文件用白話說明 exp230 做了什麼。實驗細節在 [README.md](./README.md)（英文）。

## 1. 果蠅怎麼看出「在動」

果蠅的眼睛由許多小眼組成。生物學家 Hassenstein 和 Reichardt 在 1950 年代提出一個模型，解釋果蠅怎麼判斷東西往哪邊動：

- 取兩個相鄰的感光點，把其中一個的訊號**延遲**一下，再和另一個**相乘**；
- 反方向也做一次；
- 兩者相減，正負號就是方向。

道理很直覺：如果光點從 A 移到 B，那麼「A 剛才亮」和「B 現在亮」會同時成立。這個模型後來在果蠅的神經迴路裡真的找到了對應的細胞。

這次把它做成最簡單的版本：32 個格子圍成一圈，每格只有亮或暗（1 位元），「相乘」就是 AND，「延遲」就是上一個畫面。

```
往上 = 數一數「上一刻在下面一格亮、這一刻亮」的格子
往下 = 數一數「上一刻在上面一格亮、這一刻亮」的格子
```

## 2. 讓果蠅看 Rule 30

exp225 做了一個經過證明的「人工生命」：Rule 30。它也是 32 格的圈，每一代按固定規則更新，看起來像亂數，其實每一格都由種子決定。

這次把兩者接起來：讓果蠅看 Rule 30 的 256 代，問它「這段生命往哪邊動」。

答案很一致：從 exp225 的種子出發，256 步裡有 255 步判斷「往上」，1 步「不動」，**一步都沒有「往下」**。

## 3. 證明了什麼

| 定理 | 白話 |
| --- | --- |
| **T1** `detects` | 41 條機器指令組成的程式，對**任何**輸入畫面，都算出和數學定義完全相同的結果，剛好執行 70,924 條指令後停下 |
| **T2** `shift_up`、`shift_dn` | 把畫面往上移一格，果蠅一定判斷「往上」；往下移就判斷「往下」——**只有四種畫面例外** |
| **T3** `life_moves_up` | 不論圈上是什麼狀態，看 Rule 30 走一代，「往下」永遠不會比「往上」多 |
| 推論 `watches_life` | 程式看 Rule 30 的每一步，輸出都是「往上 ≥ 往下」 |

### T2 的四個例外

證明寫到一半時卡住了，因為「移動的條紋一定被看出方向」這句話其實不對。例外是全暗、全亮、`0x55555555` 和 `0xAAAAAAAA`。後兩個是亮暗相間的條紋，往上移一格和往下移一格得到的畫面**一模一樣**，任何這類偵測器都不可能分得出方向。

這在視覺科學裡有個名字：**混疊（aliasing）**，就像電影裡車輪看起來在倒轉。證明逼著我們把這個條件寫進定理裡。

### T3 為什麼成立

逐格看 Rule 30 的規則會發現：

- 被算成「往上」的，正好是「下面鄰居亮、上面鄰居暗」的格子；
- 被算成「往下」的，只是「上面鄰居亮、下面鄰居暗」的格子裡的一部分。

在一個圈上，這兩種格子的數量一定相等（繞一圈，亮到暗和暗到亮的次數一樣多）。所以往上至少和往下一樣多。

這個論證原本只是 exp225 計畫文件裡的草稿，標著「還沒寫成 Lean」。現在它是一條定理。另外用 C 程式把 2³² 個（約 43 億）狀態全部算過一遍，結果也一樣：沒有任何一個狀態被看成往下，有 4,870,848 個狀態被看成不動。

## 4. 這個實驗的意義

- **兩個經過證明的程式接在一起**：exp225 證明了生命怎麼長，exp230 證明了觀察者怎麼看，T3 則是兩者之間的數學事實。
- **證明找出了規格的漏洞**：T2 原本的說法是錯的，寫證明時才發現四個例外。測試很難找到這種問題，因為 2³² 個狀態裡只有 4 個例外，隨機抽樣幾乎碰不到。
- **共用的工具變多了**：這次需要的幾個小引理，和 exp229 的重複，就搬進共用的 `lean/Rv32`。
