On Linux, run yi26 udev --install first, then yi26 detach. They are two different gates and they fail differently, so the order matters and so does knowing which one stopped you.

Without the udev rule the board's device node is root-only, and Connect fails with “Access denied” the instant it opens the device — before any interface is involved, and before yi26 detach could have helped. Detaching goes through that same node, so it fails with the same permission error until the rule is in place. yi26 udev on its own checks it by opening the device the way this page does.

Then the second gate. The kernel's cdc_acm driver owns these interfaces — that is what /dev/ttyACM0 is — and an interface has exactly one owner. Chrome's WebUSB does not take it away for you, so claiming fails until something else does. yi26 attach gives it back; so does replugging, or flashing anything.

While detached there is no serial port, so yi26 log and every terminal program stop seeing the board. Flashing still works — yi26 bootsel sends the same 1200-baud request over a control transfer when there is no port to set a baud rate on.
