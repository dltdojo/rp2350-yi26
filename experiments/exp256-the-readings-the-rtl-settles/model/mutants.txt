# exp256 — wrong versions of lean/Rv32/Priv.lean, each a mistake a reading of the privileged specification could
# make. privrun builds every one: nothing in a type says what a PMP entry's bits mean. What refuses them is the
# emulator, run against them on the suites model/mutants.py names, and the probes.
#
# Three of them break a theorem Priv.lean itself proves of the rule they change (`umode_default_deny`,
# `pmp_readback_napot_low_bits`); the copy drops that theorem, so that what is built is the wrong model and only that.
#
# An access that straddles an entry's edge is not here: NAPOT entries are multiples of 32 bytes and a misaligned
# load or store traps before the PMP is asked, so no access the model makes can straddle one (the RP2350 datasheet,
# section 3.8.3.3, says the same of the chip). A model that let it through could not be told from this one.
#
