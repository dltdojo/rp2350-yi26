What this page shows

The board holds 34 scripts in its firmware, the last of them 2+2=5. For each one the C shell writes the script and its starting stack into a region of memory, and hands the CPU to 881 RV32IM instructions — the kernel — that proof/Script.lean proves halt with the specification's verdict for every script of up to 1020 bytes. When the kernel meets OP_SHA256 or OP_CHECKSIG it asks the shell, which answers with SHA-256 and BIP340. The board then sends one line:

CASE round i code want minstret sigs valid name

  • code: what the kernel halted with, 0 for accept, 1 to 12 for the way the script failed;
  • want: the verdict compiled into the firmware, script.py's;
  • minstret: how many instructions the chip counted — the Lean model's count, plus 4 for the shell's way in and out, plus 4 for each call;
  • sigs, valid: how many signatures the shell checked, and how many were good.

This page runs each script again with an interpreter of its own, written in JavaScript from the specification, with its own SHA-256 and BIP340. A case is green or grey when the board's code, the verdict it carries and the page's run agree, minstret is the model's count, and the signatures are the ones the page checked too. Red is any of those not holding. The page cannot see inside the chip: that the kernel is right for every script is the proof's to say, not this page's.

中文說明

板子的韌體裡有 34 個 Bitcoin 腳本，最後一個是《一九八四》裡的 2+2=5。每個案例，C 殼層把腳本和起始堆疊寫進一塊記憶體，再把 CPU 交給 881 條 RV32IM 指令組成的解譯器（核心）。proof/Script.lean 證明了：任何 1020 位元組以內的腳本， 核心停下來時的結果都等於規格的判決。核心遇到 OP_SHA256 或 OP_CHECKSIG 時會請殼層計算， 殼層用 SHA-256 和 BIP340 回答。每跑完一個案例，板子送出一行：

CASE 輪次 編號 code want minstret sigs valid 名稱

  • code：核心停下時的結果，0 是接受，1 到 12 是失敗的原因；
  • want：編進韌體的預期判決，來自 script.py；
  • minstret：晶片數到的指令數，等於 Lean 模型的計數，加上殼層進出的 4，再加上每次呼叫的 4；
  • sigs、valid：殼層驗了幾個簽章、其中幾個有效。

這個網頁用自己的 JavaScript 解譯器（照規格另寫一份）、自己的 SHA-256 和 BIP340，把每個腳本再跑一次。 板子回報的 code、它帶的判決、網頁自己跑出的結果三者一致，minstret 等於模型的計數，簽章也和網頁驗的一樣， 格子才會是綠色或灰色；任何一項不符就是紅色。點任何一格，可以看那個腳本一步一步執行時堆疊的變化。 網頁看不到晶片內部：核心對每一個腳本都正確，是證明的工作，不是這個網頁的。

不接板子也能用：直接點格子，看 34 個腳本各自怎麼執行、為什麼被接受或拒絕。
