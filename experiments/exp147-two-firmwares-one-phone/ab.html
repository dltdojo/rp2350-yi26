The board must be in BOOTSEL right now — not running one of the two firmwares. If its LED is blinking, it is running one: put it back with flash.html first. Then press Read both halves; on a phone the same board may be listed more than once, and the live entry is the one that asks for USB permission.




  Boot the other half sends reboot(FLASH_UPDATE) at it. This
  page was built expecting that to be a try — the other half runs, and the
  next reset puts it back. Measured on hardware, that is wrong for these
  images. A flash update boot of an image with no TBYB flag is a
  completed update: the ROM treats it as bought, and because it is a
  downgrade it erases the other half's first sector. The LED changes and
  it stays changed, because there is no other half left to go back to.




  So the trial in try-before-you-buy comes from the flag, not from the
  flash update boot. Without it this button is one-way. Reinstall the pair with
  pflash.html to get both halves back.




  Switch permanently rewrites four bytes: the other half's VERSION word,
  set above this one's. The ROM then boots it every time, because that is the
  only rule it uses. One sector is erased and written; if that fails, the half
  being switched *to* is the damaged one and the half you are on still boots.




  To do it again, put the board back into BOOTSEL — flash.html
  from a phone. And to install the pair in the first place, use
  pflash.html with the assembled exp147-ab.uf2.
