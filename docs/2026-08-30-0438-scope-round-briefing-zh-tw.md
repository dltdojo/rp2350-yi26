### exp193 的核心發現，已在板子上成立

它被建來測「牆是 configuration descriptor」，**然後推翻了這句話**：

| lane | shape | 介面 | descriptor bytes | |
| --- | --- | --- | --- | --- |
| narrow | hid 0 | 2 | 70 | console 自己 |
| narrow | hid 2 | 4 | 136 | |
| narrow | **hid 3** | — | — | **enumerate 失敗** |
| wide | hid 5 | 7 | 235 | |
| wide | **hid 6** | — | — | **enumerate 失敗** |

板子在第五個介面停住時，256 bytes 只花了 136，**還剩 120**。第一面牆是
`embassy-usb` 的 `MAX_INTERFACE_COUNT`，一個 `heapless::Vec` 的容量，預設 4。
把它調到 8，牆才移到 byte 數（268 > 256）。每介面剛好 **33 bytes**。

對元件設計的意義，已寫進 crate 文件：**`cdc_console::open` 在呼叫者加任何東西
之前，就先花掉 4 個介面裡的 2 個。**

兩面牆都是 USB 存在前的 panic —— 沒有 log、沒有 CDC、沒有 1200-baud watcher。
`lifeline` 兩次都在 **1 秒**內把板子送進 bootloader、掛出磁碟，由當時正在跑的
腳本重燒。**全程沒有人在房間裡。**

## 檢討

### 一、我一開始把收益算低了，因為沒去量產出速率

第一版評估的結論是「舊的 75 支不動、只給新實驗用，收益有限」。那是錯的，
而且錯得很基本：我沒有跑

```sh
git log --since=30.days --diff-filter=A     # 30 天內新增 91 支實驗
```

每天約 3 支。這個輪子不是「已經造了 75 次」，是**每天還在造 3 次**。

**下次怎麼不再犯**：評估任何「要不要抽取」之前，先量**產出速率**，不只量存量。
存量決定一次性的清理成本，速率決定持續的出血速度，而後者才是決定要不要動手的
那個數字。

### 二、抽取差點靜默地弄壞裁決全部 92 支的檢查

`lib.sh` 的 `usb_check` 是**用 grep 讀 `src/main.rs`** 來核對 `USB_IFACE`
宣告的介面是否真的有建。把 `CdcAcmClass::new` 搬進 crate，exp190 誠實的
`cdc` 會變成謊報。

最順手的「修好」是放寬 grep —— 而那會讓整個交叉核對從此驗不到東西。那段
grep 旁邊的註解自己寫著：因為檢查順序的關係，這個核對曾經**連續四支實驗都
沒有真的跑到**。

實際做法是**列出兩種拼法**而不是放寬，並做了三個對照：舊樣式對新樹只有
exp190 翻紅、新樣式對 76 支全過、沒有任何一支的裁決移動。

**下次怎麼不再犯**：搬動任何東西之前，先問「有沒有東西在用它的位置當證據」。
在這個 repo 裡，答案經常是 harness。而修 harness 時，**放寬樣式**幾乎永遠是
錯的方向。

### 三、`capture_header` 第一次跑就自己說謊

它在 `tee capture.txt` 的管線裡執行，所以 `git status --porcelain` 永遠看到
那個檔案被修改，**每一份紀錄都報 dirty** —— 包括從乾淨 checkout 產生的那份。
一個每次都亮的警告，一天內就等於沒有。

**下次怎麼不再犯**：任何「異常時才亮」的訊號，寫完的第一件事是確認它在**正常
情況下不亮**。這比確認它在異常情況下會亮更容易被跳過。

### 四、我差點把一個比證據更寬的宣稱寫進 README

exp193 的 README 初稿寫著「這個 repo 從來沒設過那個 feature」。實際上
**exp148–155 和 exp161 共 8 支早就設了**，各自的 `Cargo.toml` 還寫了理由。

抓到它是因為表格裡有一格我當時寫成「`2 + 2 + 1 = 5`？不 —— measured」——
那個問號是我自己不確定的痕跡，而我去查了。

**下次怎麼不再犯**：草稿裡任何帶著「應該」「大概」「不確定」痕跡的句子，
是**必須查證的清單**，不是待潤飾的文字。修正後的版本比錯的版本更有價值：
8 支知道並寫下來了，32 支在預設值底下沒提過，而 crate 花掉一半這件事是任何
一支實驗的 `Cargo.toml` 註解都承載不了的。

### 五、實驗的第一次執行推翻了它自己的前提，這是對的

exp193 建來測 descriptor 預算，第一次跑就發現牆在別的地方。這不是失敗，
是這支實驗**能被抓到說錯**的證明 —— 而它能被抓到，是因為它有一個可以走進去
的數字，而不只是「複合裝置有沒有 enumerate」。

一支只證明「它動了」的實驗，會因為它的建構方式而必然通過。那是
[exp140](../experiments/exp140-a-checksum-that-passes/) 的主題。

**值得複製**：每一支新實驗都要有一個「可以往昂貴方向失敗」的 arm。exp190 是
`late`（不該交出板子卻交了），exp193 是**宣稱與 enumerate 不符**（靜默掉了
一個介面的板子，會 enumerate、會 log、會回應 1200-baud，卻是錯的）。

## 這一輪做對的三件事，值得複製

1. **棘輪，不是重寫。** 92 支不可能回頭改，每支都要一次上板。
   `duplication-baseline.txt` grandfather 現有的 53 個重複函式，`--check` 只在
   數字上升時失敗。不要求任何人修好過去，只要求第 93 支不要再加。
   而且做了負向對照：塞一支帶複本的假實驗進去 → `FAIL console_task(17->18)`。

2. **不要跑在呼叫者前面。** `cdc-console` 第一版刻意沒有交回 `Builder` 的方法。
   等 exp193 真的需要時，由**存在的呼叫者**決定形狀，並在同一輪上板驗證 ——
   然後立刻推翻了 crate 文件自己帶著的假設。一個為不存在的呼叫者設計的 API，
   是一個沒有人抓得到它說錯的 API。

3. **證據要有日期。** 在韌體共用 crate 之前，「這份紀錄還描述現在的程式碼嗎」
   只能用猜的。crate 的 bug 對**它之後建的每一支韌體**都是錯的，包括紀錄早於
   它、看起來還在 PASS 的那些。`capture_header` 讓「哪些紀錄早於這次修正」
   有答案 —— 而它第一次適用就用上了：exp190 的紀錄早於 crate 改動，所以重跑。
