# 一個位址,三種到不了的方式

- **日期:** 2026 年 8 月 5 日
- **語言:** 正體中文
- **對應進度:** exp150,共 50 個實驗

---

板子端出自己的網頁,這是整條路的獎品。`tools/pages/` 裡每一頁都活在同一組限制裡:必須是 Chromium、必須有 WebUSB、必須點過一個權限對話框、必須在一個會列出同一塊板子三次的裝置選單裡挑對。**一塊自己服務網頁的板子,一樣都不需要。**

代價要並排寫,因為它是永久的:`http://` 不是 secure context,所以這塊板子端出來的那個 origin,**永遠不能再用 WebUSB**。這條路開了一扇門,同時關上另一扇。

在桌機上,連線到回應是 **3 毫秒** — 而回應的那顆晶片,同時還在跑發位址給主機的 DHCP 伺服器。

## 兩個只有板子找得到的 bug

兩個都在連線的**拆除**那一段,兩個都通過了所有靜態檢查。

**第一個:等一個 TCP 永遠不會到的狀態。**

```
連續發:      200 000 000 000 000
每秒發一個:  200 200 200 200 200
```

正常關閉的 socket 會進 **TIME-WAIT,不是 `Closed`**,而且在那裡待大約十秒。所以那個等 `Closed` 的迴圈每次都跑滿兩秒的保險期限,等於每個請求讓一個工作者兩秒不監聽。兩個工作者就是剛好兩個請求。

而**測試之間留一秒的間隔,會把它完全藏起來。**

**第二個:工作者的數量就是併發上限。** smoltcp 沒有 listen backlog,一個找不到監聽 socket 的 SYN 是被拒絕、不是排隊。所以 N 個工作者剛好服務 N 條同時連線,第 N+1 條失敗。瀏覽器載一個頁面加一個 favicon 就要兩條。

改成四個之後量到的 `000 000 200 200 200 200`(同時六條)不是失敗,**那是這個設計的性質**,而它值得在有人拿壓力測試工具指著它之前先寫下來。

## 手機那邊:同一個位址,三種到不了

拿一支手機來,一切就變了。Chrome 打 `http://192.168.7.1/` 回 **`ERR_TIMED_OUT`**,而板子在 245 秒裡記錄 **`0 request(s) served`** — 一條連線都沒到。

錯誤碼本身就是診斷。不是「位址不可達」也不是「連線被拒絕」,所以封包**從某條路出去了**,只是沒有人回答。它們走了手機的預設網路,而一個私有位址在那裡會被丟掉。

然後把角色對調,它就通了。

## 位址必須是手機給的

用 Android 的**乙太網路數據連線**,手機當 DHCP 伺服器兼路由器,板子當客戶端 — 那是 Android 支援的那種安排。板子拿到 `10.206.115.123`、一個 gateway,而它的網頁**在手機的 Chrome 裡渲染出來了**。

一塊自己指定位址的板子碰不到;一塊**被指定位址**的板子碰得到。

## 而且只能用導航,不能用抓的

`reach.html` 一次試了三種方式,因為它們會各自失敗:

| | 手機上的結果 | 為什麼 |
| --- | --- | --- |
| `fetch()` | 送出之前就被拒 | `content://` 頁面去抓 `http://` 是**混合內容** |
| `<iframe>` | 空白 | 把 `http://` 嵌進安全頁面,一樣是混合內容 |
| **導航** | **頁面出來** | 頂層導航**沒有頁面可以被混進去** |

這是值得留下的那個發現:**限制的對象不是「連到私有位址」,是「把不安全的東西混進安全頁面」。** 導航沒有東西可混,所以它過。

這也表示 `fetch` 那個按鈕在手機上**永遠**不會是儀器,板子送再多 CORS 標頭都沒用 — 因為那根本不是 CORS 的決定。

## 一個被收回的解釋

第一次寫進 repo 的解釋是「這個介面從來沒有變成 Android 認得的網路」。

然後**同一份韌體重新插一次**,Android 的乙太網路數據連線開關 — 在那之前是灰的 — 變成可選了。而數據連線需要一個 Android **已經認出是乙太網路**的介面。所以那個解釋不成立。

會這樣寫是因為我準備做一個一位元的實驗來「證實」它,而拿著手機的那個人問了一個問題:**如果之前沒人看過那一頁,你怎麼知道它本來是灰的?**

沒有「之前」的觀察,「之後」就證明不了任何事。那個問題擋下了一次會把假因果寫進紀錄的實驗。

所以 repo 裡現在測量和解釋是分開的:**測量成立,解釋收回。**

## 順帶退場的一個風險

行動數據在每一種情況下都活著 — **包括那個把板子宣告成 gateway 的版本**,而那是大家最怕的最壞情況。

一個 USB 乙太網路裝置在這支手機上不會擠掉任何東西。它也不會替你載任何東西。
