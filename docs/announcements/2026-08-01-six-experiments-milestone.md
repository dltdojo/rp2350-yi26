# 六個實驗的段落

- **日期:** 2026 年 8 月 1 日
- **語言:** 正體中文
- **對應進度:** exp101 – exp106,尚無正式版本釋出

---

這陣子在做一個公開的練習專案 rp2350-yi26,用 Rust 搭配 Embassy 非同步框架,在 Raspberry Pi Pico 2(RP2350)上做一系列循序漸進的實驗。目標很單純,讓一個剛買到板子、手上只有一條 USB 線的人,能一步一步走到寫得出韌體。

整條路線刻意守著一個原則,就是前期不讓使用者再花錢買任何東西。沒有燒錄器、沒有麵包板、沒有杜邦線,只要板子和線。這個限制看起來綁手綁腳,實際上逼出了不少有意思的解法。

第一個實驗甚至完全不碰 Rust,只做一件事,確認板子、線、主機三者看得到彼此。理由是先把硬體環節排除掉,之後任何失敗都可以確定是軟體問題,而不是一條沒有資料線的充電線在作怪,那其實是新手回報「我的板子壞了」最常見的原因。

接下來才是安裝工具鏈、把原始碼編成韌體、燒進去讓 LED 閃起來。這一段最花心思的反而是解釋那些會嚇到人的現象,例如把韌體檔案拷貝進去的瞬間,那個磁碟就會消失不見,連檔案管理員都可能跳出錯誤訊息。那不是失敗,那正是成功的訊號。

再往後,板子學會透過 USB 序列埠說話。然後是我自己最喜歡的一段,讓韌體監聽主機把序列埠設成 1200 baud 的動作,一收到就自己重開進燒錄模式。從那一刻起再也不必按著 BOOTSEL 拔插 USB 線,整個修改、編譯、燒錄的循環變成純軟體操作。

最新的實驗則是把 BOOTSEL 變成一般的使用者按鍵。Pico 2 其實沒有給使用者用的按鍵,而 BOOTSEL 接在快閃記憶體的晶片選擇線上,要讀它必須把那條線暫時浮空、關掉中斷,取樣的程式碼還得放在記憶體裡執行,因為那當下快閃記憶體是讀不到的,偏偏程式正是從那裡執行。韌體會在開機時實測這個動作的耗時再印出來,在我的板子上是每次二十點七微秒。這個數字比講一句「這個操作很貴」有用得多。

專案的開發流程本身也一併記在 repo 裡。每個新實驗動工之前都要先被拷問一輪,確認它只證明一件事,確認沒有偷偷增加硬體需求。還有一條規矩是沒有在真板子上驗證過的東西不推上 GitHub,這條規矩已經擋下一次,某個實驗編譯得漂漂亮亮,燒進去卻完全不動,原因是重置晶片的時機太早,把 USB 控制傳輸從中間打斷了。那次失敗現在留在該實驗的說明文件裡當教材。

另外也放了一支揭露腳本,會把每個韌體裡那些為了方便而預設開啟的設定攤開來講,包括各自的風險和怎麼關掉。畢竟讓主機隨時能把板子踢進燒錄模式,開發時很方便,換個場合就不見得是好事。

目前還沒有正式的版本釋出,不過六個實驗跑完,從環境確認一路到輸入驅動輸出,算是走到了一個像樣的段落。
