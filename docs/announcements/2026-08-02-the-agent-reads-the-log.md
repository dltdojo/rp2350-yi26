# 誰在讀那份日誌

- **日期:** 2026 年 8 月 2 日
- **語言:** 正體中文
- **對應進度:** exp118、exp119,加上 AGENTS.md,尚無正式版本釋出

---

這篇跟前兩篇不同,講的不是專案做了什麼,是**專案是怎麼被做出來的**,因為那件事在這幾天變成了會影響設計決定的東西。

現在這個 repo 有相當比例的工作是 AI 代理在做,而人不一定在板子旁邊。這聽起來像是效率問題,實際上它會改變「哪些工作現在可以進行」。而這件事第一次真的咬到我,是在一個很小的地方:我需要知道韌體印了什麼,而我去開了使用者的瀏覽器、截了一張圖來看。

那個做法是會動的,而且它錯得很徹底。專案裡花了兩個實驗做出來的那些網頁,存在的理由是讓**一個人**在沒有工具鏈的機器上看到日誌 —— 手機是最重要的那個情境。那些網頁是產品。主機端那支工具才是量測儀器。拿產品當儀器去量,不只慢,還會產生一張圖片,而當下明明有一份 JSON 可以拿;更要命的是它需要有人在場去授權、去開著視窗,而這裡的開發預設是不需要互動的,每一個需要人在房間裡的步驟,都是一個到了晚上就會停下來的步驟。

所以這條規矩被寫進 repo 的根目錄,寫成一份專門給代理看的文件,而且刻意寫得很短,只放代理專屬的規則,其他的都指向既有文件,免得同一條規矩有兩份會慢慢分岔的副本。核心那句話講的是用途而不是機制:**瀏覽器永遠不是你讀日誌的方式,它只會是被測試的對象。** 要知道韌體印了什麼,就用工具;要確認一個網頁能不能接管介面、能不能串流、畫面對不對,那就開瀏覽器,因為那時候網頁本身才是題目。同樣的提醒也放進每個網頁的檔頭註解,而且實驗的檢查腳本會斷言那段註解還在,所以它不會被誰無聲地刪掉。

規矩定下來之後,才發現它其實決定了工作順序。瀏覽器那條路的每個實驗都需要人按一次原生對話框,而那個授權的行為也被量過了:它綁在 file:// 這個來源整體而不是綁檔案路徑,所以一個從沒開過的新網頁會直接繼承它;但它撐不過瀏覽器行程結束,重開一次就要重按一次。順帶一提,這個量測推翻了我自己先前寫下的一句話,而那句錯話差點讓整條瀏覽器軌道被合併成一個大網頁,為了省一個根本不存在的成本。

結論是:韌體和主機端的工作不需要任何人,瀏覽器的工作一定需要。所以當板子連得上而它的主人不在,能推進的就是不需要人的那些,於是兩個實驗插隊做完了,編號留著空格,因為理由本身值得留在紀錄裡。

插隊做的第一個是讓韌體開始聽。這聽起來像是加一個 task 就好,結果不是。CDC 的接收端同時是唯一能讀到主機 baud rate 的地方,而那個 baud rate 正是第五個實驗做的自動重開機所依賴的東西;監聽主機送來的位元組又需要對同一個物件的可變借用。給讀取者,板子就再也不能自己重開,只能靠人按按鈕;給監看者,就沒有東西能聽。**一個 task 必須同時做兩件事**,於是要同時等待兩件事的那個寫法出現了 —— 它是被所有權逼出來的,不是被挑出來的。這是這個 repo 第一個由所有權而不是品味決定形狀的韌體。

那個實驗還順手證實了一件常被說錯的事:主機送一次一百個位元組,裝置會收到兩次,六十四加三十六。USB 沒有「訊息」這種東西,只有封包,而且沒有長度前綴也沒有分隔符號。想要訊息的韌體必須自己定義什麼叫一則訊息並且自己重組。

第二個實驗回答前一個留下的問題:同時等待兩件事的寫法會丟棄輸掉的那一個,那會不會弄丟一個封包。答案是不會,而理由值得看 —— 驅動程式裡整個讀取只有一個暫停點,而它發生在資料被取用**之前**,並且它等待的是硬體暫存器,沒有人取用就不會被清掉。這跟前一個實驗依賴的機制完全不同,那邊靠的是一個軟體旗標的閂鎖。同樣的保證,無關的兩個理由,所以不能從其中一個推導出另一個,只能量。量的結果是兩萬個封包、一萬九千多次取消、零遺失。

不過這個實驗真正在乎的數字不是遺失數,是取消數。一輪什麼都沒掉、只是因為根本沒有發生過取消,那不是證據而是幻覺,所以韌體會直接印出「這一輪什麼都沒測到」,而不是印一個看起來很安心的零;檢查腳本也是先驗證那個對照變數,才驗證結果。

最後是三個被修掉的錯誤訊息,它們是同一種毛病:**建議跟故障對不上**。工具對著一塊正在正常運作的板子說「請換一條資料線」,只因為它的介面被交給了瀏覽器所以沒有序列埠;網頁把每一次接管失敗都怪到核心驅動程式頭上,但同樣的錯誤也可能只是另一個分頁還開著;燒錄指令在裝置節點剛出現的瞬間就宣告成功,而下一道指令會因為權限還沒套上而失敗。三個都會把人送去修一個沒有壞的東西。

在一個大部分時間由代理推進的專案裡,這類訊息的品質不是禮貌問題。跟著錯誤建議跑掉的那個,常常就是代理自己。
