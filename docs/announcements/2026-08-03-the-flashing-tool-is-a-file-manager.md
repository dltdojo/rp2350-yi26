# 燒錄工具是檔案管理員

- **日期:** 2026 年 8 月 3 日
- **語言:** 正體中文
- **對應進度:** exp101 – exp128,以及 docs/platforms.md 的手機燒錄驗證,尚無正式版本釋出

---

上一篇說的是板子自己端出除錯介面,也就是資訊從板子流向人的那個方向。這一篇是反過來的那一半:**在完全不買一台開發用電腦的前提下,怎麼把韌體寫進板子。**

先說為什麼這件事在微控制器的實務裡不常見。一般情況下,燒錄需要工具:廠商的整合開發環境、命令列的燒錄程式、或者一根除錯探棒。那些東西都要裝在一台你擁有的電腦上,而且幾乎都只有桌面作業系統的版本。於是「開發微控制器」這件事,門檻裡有一項是「先有一台電腦」,而且通常是特定的那幾種。

RP2350 這顆晶片有一個地方不一樣,而這個專案從第一個實驗起就在用它,只是一直沒有把它推到極限。按住 BOOTSEL 上電,晶片的唯讀記憶體會讓自己看起來像一顆小小的隨身碟,把 UF2 檔案拖進去就是完整的燒錄程序。那不是作業系統的功勞,是晶片自己做的,所以任何看得懂隨身碟的東西都能當燒錄工具——包括一支手機的檔案管理員。

這個推論一直寫在這個 repo 的文件裡,但**從來沒有人真的跑過**,而中間有一步沒有理由假設它會成立:Android 到底准不准你把檔案**寫進**一顆外接的 USB 磁碟。那不是 RP2350 決定的,是手機儲存層決定的,而各家 Android 對可移除媒體的寫入權限一向有各自的脾氣。

八月三日,在一支 Google Pixel 9a 上,配一條 OTG 線,沒有別的東西:寫入成功了。板子重開進新韌體,手機掛上了那個韌體自己排出來的磁碟區,點開裡面的 README.TXT,最後一行是建置之前才被加進原始碼的一句標記。那句話不存在於任何其他檔案裡,所以它沒有別的地方可以來。

有三個數字在手機畫面上自己對上了,沒有人去比對它們。README.TXT 顯示 646 B,那正是原始碼裡那個字串常數加上那行標記之後的長度;INDEX.HTM 顯示 19.31 KB,而檢查腳本裡寫著 19309 位元組,那是它跟另一個實驗的網頁逐位元組比對過的大小;兩個檔案的日期時間一模一樣,因為那是開機時手刻進目錄項目的 FAT 時間戳,不是主機給的。三個數字分別來自原始碼、來自檢查腳本、來自晶片的記憶體,而它們在一支從來沒看過這個專案的手機上湊在一起。

還有一件沒有人設計的事。掛載之後不到一分鐘,Android 自己在那個磁碟區上建了一個 LOST.DIR 目錄——它對可移除媒體就是會這樣做。在這個實驗裡那次寫入落在晶片自己的 64 KiB 靜態記憶體上,下次重置就消失,無害;但它同時是**手機確實握有寫入權而不只是讀取權**最直接的證據,也是一個值得先知道的警告:如果哪天把這種磁碟區搬進快閃記憶體,主機會在你沒同意的情況下往裡面寫東西。

順帶說一個讓這個結果站得更穩的細節。這個專案有兩塊官方 Pico 2,一塊跟著 Ubuntu 機器,一塊跟著手機,各守一台,不互換。手機燒的是後者,而它**從來沒有接過那台建置韌體的機器**。所以「那個韌體怎麼跑到板子上的」這個問題只有一個答案。

也要把沒有證明的部分講清楚,因為這個 repo 的規矩是不宣稱沒驗證過的東西。這次那個 UF2 是在一台它主人自己擁有的 Linux 機器上建的,不是租來的,所以這一趟驗證的是**燒錄那一半**。建置那一半是八月二日另外驗證的:從一次乾淨的 git clone、在這個 repo 沒見過的目錄裡,五個實驗全部編譯、轉成 UF2、家族識別碼正確,而且在**沒有任何板子**的情況下,檢查腳本印出五個通過、一個略過,結束碼是零——沒有板子不是失敗。那個 UF2 後來真的燒進板子跑起來了。兩半都有證據,但**還沒有人在一次連續的流程裡、以一個既沒有 Linux 機器也沒有編譯器的身分把它跑完**,而那才是這條路線的完整宣稱。

那句「檢查腳本在沒有板子的情況下結束碼是零」是整件事的關鍵,值得單獨說。它的意思是:在雲端那台機器上改完程式碼,你可以在**下載那個檔案之前**就知道它建得起來、格式對、該有的建置選項在裡面。真正需要板子的部分會誠實地略過而不是假裝通過。剩下唯一無法在雲端回答的問題,就是它在真實硬體上跑不跑得起來——而那正是手機那一半的工作。

這條路對誰有用?最明顯的一群是**本來就打算插在手機上的裝置**。如果你做的東西的使用情境就是接在一支手機上,那麼開發迴圈跟部署環境是同一台機器,你不需要為了開發而多買一台桌機。往下延伸一點,任何在現場、在移動中、或是手邊只有一支手機的時刻,都可以做完整的「改一行、重建、燒錄、看結果」——只要那台雲端機器連得上。

還有沒有非要電腦不可的部分?有兩處,講清楚比較誠實。第一個實驗做不了,因為它問的正是「你的板子、線材和主機看不看得見彼此」,而那需要主機上的那幾支命令列工具;讀那一篇然後從第二個實驗開始就好。另外,讀序列埠的日誌在手機上要靠瀏覽器那條軌道,而那條軌道只在 Chromium 系的瀏覽器上成立——桌面上那個顯而易見的 Web Serial 介面在 Android 上根本不存在,這也是當初整條軌道會走 WebUSB 的原因。

到今天是二十八個實驗,每一個都在真的板子上驗證過,每一個都有一份非互動式的檢查腳本會給出通過或失敗。而現在那份文件裡關於手機的段落,不再是一段推論。
