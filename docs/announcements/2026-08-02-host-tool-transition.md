# 把不可攜的部分收成一支工具

- **日期:** 2026 年 8 月 2 日
- **語言:** 正體中文
- **對應進度:** exp101 – exp107 加上 tools/yi26,尚無正式版本釋出

---

這幾天做的東西不是新的實驗,而是主機端的一支小工具,不過促成它的判斷過程大概比工具本身更值得講。

起點只是一個懷疑。整套實驗的腳本都靠 cat、grep、stty、lsusb 這些指令在跟板子打交道,而這些東西在別人的機器上會不會有一樣的行為,其實沒有人知道。與其猜,先去量:把所有腳本用到的外部指令數過一遍,真正綁死 Linux 的只有五個函式、大約四十行,而且全部集中在同一個檔案裡。要動的面積比想像中小得多,這是先前立下的「共用的東西集中放一份」那條規矩在還債。

不過真正說服我動手的理由不是可攜性。現在的腳本吐出來的是給人讀的散文,一個幫你除錯的 AI 代理拿到那種輸出,只能用正規表示式去猜。所以這支工具從一開始就把機器可讀的輸出當成頭等公民,而不是附屬品:一個指令回傳主機平台、工具鏈裝了沒、板子在哪個模式、序列埠和燒錄磁碟在哪裡,還有一份問題清單,每一筆都帶著識別碼、嚴重程度和修法。韌體自己的記錄也會被拆成時間戳、掉了幾行、內容,最後附一個摘要說總共漏掉多少、跨多長的時間。這是 cat 加 grep 生不出來的東西。

方向上選了取代而不是並存。同一件事留兩份實作,結果一定是其中一份是錯的而且沒有人發現,因為實際上只有一份會被跑到。

但取代不等於藏起來。這是一個教學用的專案,「把序列埠設成 1200 baud,板子就會自己重開」這種事本身就是教材,不能因為換成工具就讓使用者再也看不到那行指令。所以每個子命令都可以加上一個參數,它會先把等價的手打指令印出來、順便解釋為什麼得那樣打,然後才真的去做。有些事情本來就沒有等價的手打指令,那就明講沒有,並且說明原因,因為「用工具就好」不算解釋。

過程中冒出一個沒預期的例外。第一個實驗不能用這支工具,因為它跑在安裝 Rust 之前,不可能依賴一個要先編譯的東西;而且把那幾個原始指令直接攤開來給使用者看,正是那個實驗的教材本身。這個例外不是品味問題,是實驗的先後順序逼出來的,所以它被寫進程式碼和文件裡,標明是刻意保留的。

也照例踩到坑。腳本裡包裝這支工具的函式,名字跟工具本身一樣,而 shell 在找東西的時候會先找到函式,於是它把自己指向自己,無聲地遞迴下去,最後回傳一個空字串,狀態碼還顯示成功。看起來一切正常,實際上什麼都沒做。這種錯誤光看程式碼是看不出來的,得真的跑過。

最後是邊界。這支工具用的是可攜的函式庫,macOS 和 Windows 的路徑也都寫了,但沒有人在那些系統上跑過。文件寫的就是「只在 Ubuntu 驗證過,其他平台未驗證」,而不是「跨平台」。這個專案有一條規矩是沒有在真機上驗證過的東西不推上去,而「在你的機器上也會一樣」剛好就是一句我們驗不了的話,那就照實說。

工具不是這個專案的目標,實驗才是。但如果有人正在把一堆類似的腳本收斂成工具,或者正在讓 AI 代理幫忙除錯自己的嵌入式專案,這次的取捨過程也許比那支工具本身更有參考價值。
