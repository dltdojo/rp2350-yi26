## 一句話

**用 Rust + Embassy 把 RP2350 的 USB 控制器從頭到尾摸過一遍，每一步都在真板子上跑過才寫下來。**

技術選型是排他的，不是偏好問題：

| 用 | 不用 |
| --- | --- |
| `no_std` Rust | C / C++ |
| [Embassy](https://embassy.dev) 非同步框架 | Pico SDK |
| `embassy-usb` 裝置堆疊 | TinyUSB |
| `async` / `await` | 阻塞式 HAL、RTOS 執行緒 |

選 Rust 的理由集中在 USB 這個特定領域：描述元解析和端點緩衝區正是 C 韌體最容易
寫爆的地方，而借用檢查器在編譯期就把那一類錯誤排除，執行期零成本。周邊所有權
被 move 而非按慣例共享，所以兩段程式碼不可能同時驅動同一個端點。

選 Embassy 的理由更直接：**USB 裝置本質上就是一堆大多時間閒置、由中斷驅動的並行
狀態機** —— 控制管線、每個類別介面、每個端點。`await` 直接表達「等下一個 SETUP
封包」，不必在中斷處理常式裡手刻狀態機。

## 標的硬體

[RP2350](https://www.raspberrypi.com/products/rp2350/)，Raspberry Pi Pico 2 上的微控制器：

- 雙核心，可在 Arm Cortex-M33 與 RISC-V Hazard3 之間切換
- 520 KB 晶片內 SRAM
- USB 1.1 控制器，**device 與 host 雙角色**
- 3 個 PIO 區塊 / 12 個狀態機
- 安全功能：Arm TrustZone-M、簽章開機、OTP

**幾乎不綁特定板子。** BOOTSEL、UF2 開機磁碟、USB 控制器全部住在 RP2350 自己的
ROM 與矽晶片裡，任何 RP2350 設計的行為都一樣。只有兩件事跟板子有關，而且都是
改一行：LED 的 GPIO（預設 `PIN_25`），以及封裝 feature（`rp235xa` 30 腳 vs
`rp235xb` 48 腳）。驗證一律在正式版 Pico 2（non-W）上做。

## 實驗地圖

53 個實驗不是平鋪的清單，而是幾條各有終點的軌道。

### 起步（exp101 – exp103）

證明三件事各自獨立成立：**硬體鏈**（板子、線、主機看得到彼此，還沒有 Rust）、
**編譯鏈**（這台機器能交叉編譯 RP2350 韌體，不需要板子）、**兩者接起來**
（原始碼變成會閃的 LED）。

exp103 是整個 repo 最簡單的韌體，卻是最難自動驗證的一個 —— 原因見下面的 Needs 分級。

### USB 基礎（exp104 – exp107）

板子透過 CDC-ACM 回話；韌體把自己送進 bootloader，**BOOTSEL 按鈕從此退休**
（exp105 之後的韌體都能靠 1200-baud touch 自己重開）；三個任務共用一條序列日誌，
而且印東西不會卡住工作。

### 晶片自己的感測器與熵源（exp108 – exp114）

這一段從「讀溫度」開始，很快變成一串關於**如何不被自己的測試騙**的實驗：

- **exp109** —— 真實熵源，以及索取它的代價：一個**錯了好幾千倍**的驅動預設值
- **exp111** —— 兩個看起來都很隨機的來源，以及兩個廉價測試能與不能告訴你的事
- **exp112** —— 一個悄悄不再使用硬體 RNG 的建置，以及**每一個沒察覺的測試**
- **exp113** —— 一個板子自己 46 毫秒就能窮舉的種子：為什麼「空間大」不等於「熵高」
- **exp114** —— SP 800-90B 規定的兩個連續測試，以及一個測試失敗就拒絕輸出的來源

### 瀏覽器軌，已完成（exp115 – exp126）

十二個實驗指向同一個目的地：**用手機除錯韌體**。板子插進 Android 手機，開一個
網頁，讀裝置自己的日誌 —— 不裝 app、不用第二台電腦、不用除錯探針。

之所以重要，是因為**手機是最難對付的主機**：它唯一的 USB 埠正被待測裝置佔著，
所以 `adb` 剛好在你最需要的時候不能用，而原廠手機上沒有 Wireshark。當你無法從
主機端觀察，裝置就必須觀察自己，而你必須能在手機上讀到。

兩個事實決定了整條軌道的形狀：

- **Android 版 Chrome 有 WebUSB，沒有 Web Serial。** 那個「顯然該用」的 API 只在桌機上有，在這裡毫無用處。
- **WebUSB 可以直接接管 CDC-ACM 介面。** 它自己送 `SET_LINE_CODING` 和 `SET_CONTROL_LINE_STATE`，自己讀 bulk IN 端點 —— 所以前三個實驗**完全沒改韌體**。

終點：一支只有一個 USB 埠的手機可以**燒錄**板子（exp117）、**跟它對話**
（exp120）、**讀它的日誌**（exp116），而且日誌頁面是從板子本身供應的（exp126）。

exp126 收掉了一個從 exp101 就打開的迴圈：按住 BOOTSEL 時出現的 `RP2350` 磁碟
**根本不是真的磁碟** —— bootrom 即時合成一個 FAT 卷，連 `INDEX.HTM` 都是假的。
讓第一個實驗成立的把戲，正是最後一個實驗蓋出來的東西。

兩個代價在規劃時就講明，至今仍然成立：`embassy-usb` 沒有 MSC 類別，所以
Bulk-Only Transport 和 SCSI 子集都是手刻的（這就是 exp123–126 要分四步而不是
一次落地四百行的原因）；而 WebUSB 只有 Chromium 有 —— Firefox 和 Safari 都不
實作，這讓 exp115 成為本 repo 第一個指名特定廠商軟體的實驗。**它換到的是手機，
而且只有它能換到手機。**

### 所有權與應用（exp127 – exp137）

主機用一個位元組改變板子，而 **LED 不再是韌體還活著的證據**（exp127）。接著是
一串關於「訊息邊界從哪裡來」的實驗：手工重組封包、一個沒有位元組的封包、
從中途加入資料流。還有抽獎應用：板子上的抽獎，建構上就無偏，來源失效時拒絕，
而且編號到讓被丟棄的那一抽會現形（exp129–133）。

exp134 是個漂亮的小實驗：**一個滿了的佇列可以保留最舊的行、最新的行、或什麼都不留
—— 同一個韌體的三種建置，同樣的沉默有三種讀法。**

### 更新之路（exp138 – exp147）

這條路的開場方式決定了它的全部：**先問，而不是先假設。**

關於雙韌體更新的標準建議是「開機 ROM 是固定的矽晶片，它不可能知道你要哪個 slot，
所以自己刻一個 bootloader」。這對大多數晶片是對的，**對這一顆是錯的**。RP2350 的
ROM 裡有分割表、A/B 連結、會比較的映像版本號、try-before-you-buy 旗標、
`pick_ab_parition` 和 `explicit_buy`。一塊原廠板子對上述每一個呼叫都會回答，
而且裡面**是空的**。

所以這條路不是「做一套 A/B」，而是**用已經在那裡的東西，然後量出手刻一套本來
能多買到什麼**。沿途的結果：分割表放在 flash 位移 0 於是韌體得搬家（exp139）；
一個能被四個位元組偽造成任意值的 CRC，同樣的攻擊在雜湊上失效 —— 為什麼
**可靠性**和**真實性**是兩個不同的詞（exp140）；BOOTSEL 有兩個 USB 介面，瀏覽器
接管不了磁碟但接管得了另一個，也就是 `picotool` 在驅動的那個 flash 埠（exp141）；
兩個版本不同的映像，ROM 開較高的那個，把版本對調則開另一個，選擇是活的（exp142）。

exp144 揭露了一個漂亮的不對稱：**ROM 自己的磁碟在分割表存在時拒收拖進來的
`.uf2`，而 PICOBOOT 根本不查那張表。同一塊板、同一張表，兩扇門給出相反的答案。**

exp147 把整條 A/B 弧線編排成手機跑得動的樣子，由 LED 回報答案 —— 快閃或慢閃。

### 網路之路（exp148 – exp153）

Pico 2 沒有網路介面，而且**不需要有一個才能上網**：CDC-NCM 讓它變成 USB 乙太
網路卡，而它插進去的那台機器就是線的另一端。那台機器可以是筆電，也可以是手機
—— 這才是這條路值得走的全部理由：**一塊會供應網頁的板子，任何瀏覽器都能連，
不需要 WebUSB、不需要權限選擇器、不需要 Chromium。** 整個 `tools/pages/` 軌道
活在那些限制裡，這條路是出口。

- **exp148 —— 連線不等於網路。** 韌體看得見主機驅動接管功能（在那之前
  `is_link_up()` 是 false）。但位址從來沒來，**而那就是發現本身**：Android 在
  USB 乙太網路 gadget 上跑 DHCP 客戶端，這塊板子也跑，兩個客戶端互相等對方。
  NetworkManager 一模一樣。**這個死結不是手機的問題，而是每一台主機在被告知
  之前的預設行為。**
- **exp149 —— 板子自己發位址。** `embassy-net` 的 `dhcpv4` 只有客戶端，所以想
  一插上就能連的板子必須自己回答 DHCP：UDP 67 上的四個封包，DISCOVER→OFFER、
  REQUEST→ACK，手刻而且看得見。
- **exp150 – exp152 —— 板子供應自己的網頁**，沒有 WebUSB、沒有權限對話框、
  沒有選擇器，任何瀏覽器都行；日誌在瀏覽器裡（exp151，已在手機 Chrome 上驗證
  算繪）；一個**在知道自己位址之前不存在**的磁碟（exp152）。
- **exp153 —— 從手機出去。** 板子透過它插著的那支手機連上網際網路，
  **推翻了這個 repo 自己白紙黑字寫下的「手機不能做 NAT」的主張**。

那筆網路成本量過了：相對於 exp147，多 **17,408 位元組** flash 與 **9,704 位元組**
靜態 RAM。一個裝著 TCP/IP 堆疊的韌體仍然塞得進 64 KiB 的 A/B slot，還剩 25 KiB
—— 所以**網路之路沒有把更新之路堵死**。

## 貫穿全案的方法論

這個 repo 真正的產出其實不只是 53 個實驗，還有幾個貫穿始終的規矩。

### 一、Needs 分級：這個實驗要花掉多少「人」

每個實驗都標了 0 到 3 的 **Needs**，回答一個問題：**凌晨兩點、板子插著、沒有
其他人醒著的時候，我能做哪些？**

| 級別 | 意思 | 數量 |
| --- | --- | --- |
| **0 · 完全不用** | 連板子都不用，一台機器就夠 | 2 |
| **1 · 一塊板** | 板子接著，之後純軟體 | 28 |
| **2 · 一個動作** | 一個人做一個動作，其餘軟體自己來 | 13 |
| **3 · 一個人** | **人就是量測儀器** —— 這裡沒有東西看得到結果 | 10 |

三個容易誤解的地方：

- **它描述的是完整驗證那個主張**，通常超過 `check.sh` 自己走得到的地方。
  exp127 最清楚：十七項檢查全部無人通過，**沒有一項看得出 LED 有沒有發光**。
- **級別 2 沒有說那個人得在哪裡。** 一隻手按 BOOTSEL 表示有人在工作檯前；
  點掉瀏覽器的 WebUSB 權限對話框表示有人在瀏覽器前 —— 而 exp115 之後，那可以是
  任何地方的一支手機。同一級，天差地遠的後勤。
- **級別 3 不是「比較難」，是「觀察不到」。** exp103 的閃爍 LED 是這裡最簡單的
  韌體，它是 3，因為**這個 repo 裡沒有任何軟體能看見光**。

這個數字防呆：它寫在 `check.sh` 裡緊鄰它描述的程式碼旁邊（`PRESENCE=3`），而
`lib.sh` 的 `presence_check` 會在它和索引表不一致時失敗 —— **所以那張表沒辦法
悄悄爛成一個謊言。**

刻意不算進去的是**燒錄進這個實驗的成本**，因為那不是實驗的性質：把 exp104 放上
一塊正在跑 exp103（完全沒有 USB）的板子需要一隻手按 BOOTSEL，放上一塊正在跑
exp105 或更新的板子則不需要任何人。**同一個實驗，兩種答案**，只有看得到板子當下
狀態的東西能在兩者之間挑。

### 二、兩個腳本，一份共用程式庫

每個實驗目錄裡都有同樣兩個腳本，名字永遠一樣：

- **`run.sh`** —— 互動式導覽。帶你走過每個手動步驟，每個指令都先顯示再執行，並解釋輸出。第一次用這個。
- **`check.sh`** —— 快速判決。非互動、無提示、退出碼 0/1。已經懂了之後用這個重新驗證。

共用的輸出格式、`run_cmd` 先顯示後執行的模式、PASS/FAIL 計數、平台守衛，全部住在
一份 `lib.sh` 裡。**一份副本表示這些腳本不可能各自漂移。**

倉庫層級另外三個：`audit.sh`（揭露報告，印出每個韌體裡與安全相關的選擇、證據與
風險）、`tools/yi26`（主機端助手，腳本首次使用時自己建置）、`pack.sh`（把一個實驗
打包成沒有 checkout 的人也能燒錄的 `.zip`）。

`pack.sh` 有個值得學的設計：**它在 `check.sh` 非零退出時拒絕打包，所以一個 zip
是證據而不是願望。**

### 三、任何平台相關的東西都屬於工具，不屬於腳本

shell 腳本是**教學敘事**，工具是那些否則就得每個作業系統一份的部分的**唯一實作**。
`yi26` 的每個子指令都吃 `--explain`，印出它代替了什麼 —— **所以取代那些指令不等於
把它們藏起來。**

### 四、沒在真板子上跑過就不發布

以及一條專門寫給 AI 代理人的規矩（`AGENTS.md`）：**日誌永遠用 `yi26 log --json`
讀，永遠不要開瀏覽器去讀。** 瀏覽器只可能是被測試的對象，不會是量測儀器。一個
為了知道韌體印了什麼而去截圖瀏覽器視窗的代理人，是把待測物拿來當量尺用了 ——
它比較慢、需要有人在場批准權限並保持視窗開著，而且在一份 JSON 文件唾手可得的
情況下產出一張圖片。

## 幾個最值得帶走的發現

如果只讀五個實驗，讀這幾個：

| 實驗 | 發現 |
| --- | --- |
| **exp109** | 一個驅動預設值可以錯上好幾千倍，而一切「看起來都正常」 |
| **exp112** | 一個悄悄不再用硬體 RNG 的建置，加上每一個沒察覺的測試 |
| **exp138** | 大家白手做的 A/B 更新機制，這顆晶片的 ROM 裡本來就有 —— 用問的，不是用猜的，而且是空的 |
| **exp140** | 四個位元組就能把 CRC 偽造成任意值，同樣攻擊對雜湊失效：可靠性 ≠ 真實性 |
| **exp153** | 推翻這個 repo 自己寫下的主張 —— 而且是自己動手推翻的 |

最後一條是這個 repo 的性格：**每個新實驗都從一場審問開始**，而審問的第二步就是
「去讀你拿得到的既有成果再推導任何東西」。把一年前就回答過的事情當成新發現拿出來，
在這裡不算小錯。
